    How this is generated

    A read-only pipeline built on Cisco's nac-test (Robot Framework tests rendered from Network-as-Code YAML) runs against the public DevNet Always-On APIC. The only POSTs are aaaLogin/aaaLogout; everything else is GET /api/class|mo/…. Nothing is ever pushed to the APIC.

    1. scripts/drift_report.sh runs nac-test with the frozen baseline (16 tenants, frozen 2026-10-22 10:47 AEDT) against the live APIC, then drift_compare.py diffs tenants/VRFs/BDs/subnets/APs/EPGs by DN and counts faults.
    2. scripts/integrity_report.sh uses integrity_check.py to pull ~35 classes plus faultInst, checks the tenant → VRF → BD → EPG → contract → subject → filter graph (using APIC's own state/stateQual on each relation), and runs the nac-test integrity suite, one Robot suite per tenant.
    3. scripts/daily_report.sh runs both and daily_combine.py writes the combined summary. run.sh and build_data.py cover the base config suite and the data refresh.
    4. This page is a static render of the summary JSON. Raw summaries: data/latest/ (integrity, drift and daily .json/.md) and the earlier run in data/2026-10-22-1105/.

    Credentials come from environment variables or a local, git-ignored .env file and are never written to output. No credentials, cookies, Robot log.html/output.xml/report.html or console logs are published here. The sandbox is shared, so other DevNet users change it all the time; "broken" findings are mostly other people's lab objects, not faults in this pipeline.
